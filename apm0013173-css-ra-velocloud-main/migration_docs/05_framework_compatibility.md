# Framework compatibility

Runtime routing is FastAPI (`velocloud_app/asgi.py`, `api/urls.py`, `api/routing.py`). Default FastAPI `/docs`, `/redoc`, and `/openapi.json` endpoints are disabled; original documentation URLs remain. There is no Django/DRF import, settings bootstrap, ORM, WSGI middleware, or template engine in the runtime. Old backend names and signing salts are strings required to interpret existing records.

| Original responsibility | Native replacement | Verified scope |
|---|---|---|
| URL resolution / GenericAPIView | FastAPI compatibility route and minimal view base | All 46 POST validation and OPTIONS contracts; case, methods, redirects, prefix tests |
| DRF serializer fields | `api/validation.py` | Four unchanged declarations; required/null/blank/default/coercion/date/choice/nested/many/form differential cases |
| DRF request parsing | `api/parsers.py` | Lazy JSON/form/multipart parsing, charset and malformed input comparisons; retained field/file/text-size limits |
| Response / JSONRenderer | `api/http.py`, `api/routing.py` | Status/headers/body; original-style errors, date/numeric encoding; deferred rendering failure |
| Authentication and sessions | `velocloud_app/auth_state.py` | Real SQLite records shared with original Django oracle; see document 06 |
| CSRF | `api/csrf.py`, native cookies | Root rejection and API exemption tests, debug/prod response samples |
| Browsable API | `api/browser.py` and captured HTML/JS/CSS | Four serializer layouts, common bound errors, negotiated HTML, CSRF cookies, token-user UI |
| Swagger 2 / ReDoc | Versioned original schema and self-hosted presentation assets | JSON/YAML, format negotiation/legacy aliases, OPTIONS, UI rendering, static responses |
| Management / collectstatic | Native `manage.py` | Three repository-referenced commands; see document 09 |

`api/views.py` changes only framework imports, view bases and schema decorators; all 55 function ASTs remain identical. Serializer declarations and custom methods are retained. The small serializer API exists because default Pydantic coercion/errors/422 behavior do not match the original contract. It implements the field types this repository uses, not the full DRF framework.

Parsing remains lazy so authentication/negotiation/method handling happens in the original order. Unknown/invalid media, malformed tokens, empty bodies and unsupported methods do not silently become FastAPI defaults. Uploaded-file validation retains the original public type names where exposed in errors. Multipart processing streams rather than loading an unbounded request first.

Captured presentation artifacts are generated by development-only `api/tests/capture_reference.py`. Django/DRF licenses accompany redistributed browser assets. No CDN dependency was added. The versioned schema must be regenerated and differential tests rerun if routes/serializers intentionally change later.

Confirmed difference: native DEBUG unhandled-error traceback pages are not byte-identical to Django's developer exception pages. Production generic 500 HTML and common explicit API errors are compared. Browser linkification and arbitrary rendered data have not been exhaustively compared; representative whole-page comparisons normalize only random CSRF tokens. These are remaining parity limitations, not approved feature exclusions. Full framework-independent function preservation does not prove all input paths equivalent.
